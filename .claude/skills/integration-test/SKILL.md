# 통합 테스트 (A-SPICE SWE.5)

## 원칙
1. **인터페이스 중심**: 아키텍처에 정의된 컴포넌트 인터페이스를 통해 컴포넌트 간 연동이 올바른지 확인하는 테스트 위주로 수행한다. 컴포넌트 내부 로직 검증은 `unit-test` 범위이다.
2. 프로젝트에서 정한 커버리지 목표(예: 인터페이스/호출 관계/요구사항 커버리지)를 **100% 달성할 때까지** 테스트를 추가하는 것을 반복한다. 목표가 없으면 사용자에게 확인한다.
3. **의미 없는 테스트 금지**: 커버리지 수치만을 위한 케이스를 추가하지 않는다.
4. **Stub/Mock은 필요한 경우에만** 사용하며 과의존하지 않는다. 가능한 한 실제 컴포넌트를 연결해 검증하고, 아직 없는 컴포넌트·하드웨어·외부 시스템에 한해 대체한다.
5. 통합 순서/전략(상향·하향, 빅뱅 지양)을 정하고 기록한다.

## 검증 대상 (인터페이스별)
- 정상 호출 시퀀스와 데이터 전달 (타입·범위·단위)
- 오류 코드 전파와 예외/실패 경로
- 사전·사후 조건, 호출 순서, 타이밍
- 인터페이스 우회 접근이 없는지 (아키텍처 위반 확인)

## 설계 기법 (적극 활용)
`unit-test` 스킬과 동일하게 **경계값 분석, 동치 클래스, PICT 조합**을 활용한다. 인터페이스 파라미터 조합과 컴포넌트 간 상태 조합에 특히 PICT를 사용한다. (PICT 사용 절차는 `unit-test` 스킬 참고)

## Doxygen 주석 (모든 테스트 함수 필수)
```c
/**
 * @brief   [테스트 목적] 컴포넌트 A가 IB_Read()로 B의 센서값을 요청하면 유효 범위 값이 전달된다.
 * @tracing SWAD-IF-004, SWRS-FUN-012
 *
 * @par Input
 *   센서 원시값 = 1023 (최대 경계값)
 * @par Procedure
 *   1. B 컴포넌트를 초기화하고 입력을 설정한다.
 *   2. A에서 IB_Read()를 호출한다.
 * @par Expected
 *   리턴값 == RET_OK, 전달된 값 == 100.0 [%]
 */
ret_t test_a_reads_b_sensor_max(void);
```
목적·입력값·절차·예상 출력값 네 항목을 모두 포함한다.

## 완료 조건
- 모든 인터페이스와 요구사항(해당 통합 수준)에 테스트가 존재하고 목표 커버리지 100% 달성
- 아키텍처 인터페이스/요구사항 ↔ 통합 테스트 케이스 **양방향 추적** 갱신
- `review` 스킬로 통합 테스트 체크리스트 리뷰 완료
