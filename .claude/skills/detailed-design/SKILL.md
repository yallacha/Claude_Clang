# 소프트웨어 상세 설계 (A-SPICE SWE.3)

## 필수 규칙
1. 아키텍처 컴포넌트를 **모듈**(소스/헤더 단위)로 세분화하여 정의한다: 이름, 책임, 소속 컴포넌트, 함수 목록.
2. **프로젝트가 정한 수준(기준) 이상의 모듈은 인터페이스를 반드시 정의**한다. 기준(예: 컴포넌트 외부에 노출되거나 다른 모듈이 호출하는 모듈)이 `CLAUDE.md`/프로젝트 문서에 없으면 사용자에게 확인하고 기록한다.
3. **인터페이스가 정의된 모듈은 오직 인터페이스를 통해서만 통신**한다. 내부 함수는 `static`, 내부 데이터는 파일 범위로 은닉한다.
4. **클린코드 원칙**: 의도를 드러내는 이름, 작은 함수, 함수당 한 가지 일, 중복 제거(DRY), 매직 넘버 금지, 부작용 최소화, 깊은 중첩 회피, 주석은 '왜'만 설명.
5. **단일 책임 원칙**: 모듈과 함수 모두 변경 이유가 하나여야 한다.
6. 함수별로 입력·출력·리턴값, 동작(알고리즘/흐름/상태), 오류 처리, 사용하는 전역/정적 데이터를 기술한다.
   - 구현 규칙(`implementation` 스킬)과 일치시킨다: 모든 함수는 상태/결과 리턴값을 가지며 리턴은 마지막 한 번.

## 산출물 구성
- 모듈 구조 및 모듈 인터페이스 명세
- 함수별 상세 설계 (흐름도/의사코드/상태도)
- 컴포넌트 ↔ 모듈 ↔ 함수 **양방향 추적성** 갱신

## 점검 (완료 조건)
- 기준 이상 모듈에 인터페이스 누락 없음, 인터페이스 우회 호출 없음
- 함수·모듈의 책임이 단일함
- 상위 요구사항/아키텍처와 추적됨
- `review` 스킬로 상세 설계 체크리스트 리뷰 완료
