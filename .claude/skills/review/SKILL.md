# 산출물 리뷰 (A-SPICE SUP.2 / 기술 리뷰)

## 원칙
1. **모든 산출물은 이 스킬로 리뷰**한다. 리뷰 없이 완료로 간주하지 않는다.
2. 리뷰는 **A-SPICE 요건에 따라 산출물별 체크리스트를 개발**하고, 그 **체크리스트를 기반으로** 수행한다. 체크리스트 없는 자유 서술 리뷰는 하지 않는다.
3. 체크리스트의 기본 틀은 `references/checklists.md`에 있다. 프로젝트 특성에 맞게 항목을 추가·수정하고, 변경 이력을 남긴다.

## 절차
1. 리뷰 대상 산출물 종류와 버전을 확인한다.
2. `references/checklists.md`에서 해당 체크리스트를 선택한다. (프로젝트 전용 체크리스트가 있으면 우선)
3. 항목별로 **Pass / Fail / N/A**를 판정하고, Fail 및 N/A는 **근거(위치, 증거)**를 적는다.
4. 결함은 ID, 심각도(Major/Minor), 위치, 설명, 조치 요청으로 기록한다.
5. 결함 수정 여부를 재리뷰로 확인(closure)하고 승인 여부를 기록한다.

## 리뷰 결과 양식
```
## 리뷰 기록
- 대상: <산출물명> / 버전: <ver> / 체크리스트: <이름 vX>
- 결과: Approved | Approved with comments | Rejected

| # | 체크 항목 | 판정 | 근거/비고 |
|---|---|---|---|

### 결함 목록
| ID | 심각도 | 위치 | 설명 | 조치 | 상태 |
```

## 외부 확인 대기 항목 (결정 DEC-003)
OEM·고객·외부 담당의 답변을 받을 수 없는 항목은 **사용자가 승인한 임시 가정**으로 종결할 수 있다. 조건: ① 가정, 한계, 안전 영향, 확인 주체가 `open-issues`(또는 동등 문서)에 기록되어 있다. ② 사용자의 승인이 `docs/decisions.md`에 기록되어 있다. ③ 해당 가정이 요구 본문과 모순되지 않고 근거 열에서 역참조된다. 이 경우 리뷰어는 "외부 확인 대기"를 결함으로 세우지 않고 Closed(사용자 승인 가정)로 판정한다. 가정의 모순·누락·측정 불가는 여전히 결함이다. 사용자만 할 수 있는 조치(승인, 서면 증거 제출)가 결정 기록으로 대체되어 있으면 같은 방식으로 처리한다. 이 규칙을 적용한 항목은 리뷰 기록에 별도 표로 남긴다.

## 공통 확인 사항
- 양방향 추적성이 상·하위 산출물과 일치하는가
- 해당 스킬(`requirements-analysis`, `architecture-design`, `detailed-design`, `implementation`, `unit-test`, `integration-test`, `sw-system-test-cases`)의 필수 규칙을 모두 만족하는가
- 이전 리뷰 결함이 모두 종결되었는가
