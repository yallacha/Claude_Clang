# 요구사항 분석 (A-SPICE SWE.1)

## 분류 규칙
1. 요구사항은 **기능 요구사항**과 **비기능 요구사항**으로 구분한다.
2. **기능 안전 요구사항**은 이 문서에 섞지 않고 **별도 문서**(예: `docs/safety-requirements.md`)에서 관리한다. 본 문서에는 해당 안전 요구사항 ID를 참조만 한다.
3. 비기능 요구사항은 **품질 / 제한 / 제약사항**으로 나눈다.
   - **품질**: ISO/IEC 25010 품질 특성으로 분류한다 — 기능 적합성, 성능 효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성. 각 요구사항에 해당 특성/부특성을 명시하고 **측정 가능한 기준**을 쓴다.
   - **제한(Limitation)**: 자원·성능 한계 (메모리, 실행 시간, 부하 등).
   - **제약사항(Constraint)**: 표준, 언어, 도구, 플랫폼, 법규 등 설계 선택을 제한하는 조건.

## 작성 규칙
- 요구사항 1개 = 1개의 검증 가능한 문장. ("shall" 사용, 하나의 의무만 기술)
- 모호한 표현(적절히, 빠르게, 등) 금지. 수치·조건·단위를 명시한다.
- 각 요구사항 필수 속성: `ID`, 분류, 설명, 근거/출처, 우선순위, 검증 방법, 상태, 상위 요구사항(추적).
- ID는 불변이며 재사용하지 않는다. (예: `SWRS-FUN-001`, `SWRS-QUA-PERF-001`, `SWRS-LIM-001`, `SWRS-CON-001`)

## 양방향 추적성 (필수)
모든 요구사항은 이후 산출물과 **양방향**으로 추적되어야 한다.

| 방향 | 연결 대상 |
|---|---|
| 상위 ↔ 하위 | 시스템 요구사항 ↔ 소프트웨어 요구사항 |
| 순방향 | 요구사항 → 아키텍처 컴포넌트 → 상세 설계 모듈 → 소스 코드 → 단위/통합/적격성 테스트 케이스 |
| 역방향 | 위 각 산출물 → 근거 요구사항 |

- 추적 매트릭스를 `docs/traceability.md`(또는 프로젝트 지정 위치)에 유지한다.
- 추적 대상이 없는 요구사항(미구현/미검증)과 근거 없는 산출물(고아 항목)을 모두 점검해 보고한다.
- 요구사항 변경 시 영향받는 하위 산출물을 매트릭스로 식별한다.

## 완료 조건
- 모든 요구사항이 위 분류와 속성을 가진다.
- 일관성·모호성·검증 가능성 점검 완료.
- 추적 매트릭스에 고아/미추적 항목이 없다.
- `review` 스킬로 요구사항 체크리스트 리뷰 완료.
