# 소프트웨어 아키텍처 설계 (A-SPICE SWE.2)

## 필수 규칙
1. **컴포넌트를 정의**한다: 이름, 책임(한 문장), 포함 요구사항 ID.
2. **모든 컴포넌트는 인터페이스를 반드시 정의**한다.
   - 제공(provided)/요구(required) 인터페이스 구분
   - 함수 시그니처, 파라미터 타입·범위·단위, 리턴값/오류 코드, 사전·사후 조건, 호출 순서/타이밍, 스레드 안전성
3. **컴포넌트 간 통신은 오직 인터페이스를 통해서만** 한다. 다른 컴포넌트의 내부 데이터·함수 직접 접근, 전역 변수 공유 금지.
4. **높은 응집도, 낮은 결합도**: 한 컴포넌트는 하나의 책임 영역만 가진다. 의존 방향은 비순환이어야 하며(순환 의존 금지), 의존은 구체 구현이 아닌 인터페이스를 향한다.
5. **모듈화, 캡슐화, SOLID** 준수:
   - SRP 단일 책임 / OCP 확장에 열림·수정에 닫힘 / LSP 치환 가능성 / ISP 인터페이스 분리 / DIP 추상에 의존
   - 내부 구현·데이터는 은닉하고 공개 헤더에는 인터페이스만 노출한다.
6. 동적 거동(시퀀스, 상태, 타이밍)과 자원 소비(메모리, 실행 시간) 목표를 기술한다.
7. 설계 근거와 검토한 대안, 결정 사유를 기록한다.

## 산출물 구성
- 컴포넌트 구조도 및 의존 관계도 (Mermaid/PlantUML 가능)
- 컴포넌트 명세표 + 인터페이스 명세
- 동적 거동 다이어그램
- 요구사항 ↔ 컴포넌트 **양방향 추적성** (`requirements-analysis` 스킬의 매트릭스 갱신)

## 점검 (완료 조건)
- 인터페이스 없는 컴포넌트 없음, 인터페이스 우회 호출 없음
- 순환 의존 없음
- 모든 SW 요구사항이 1개 이상 컴포넌트에 할당됨
- `review` 스킬로 아키텍처 체크리스트 리뷰 완료
